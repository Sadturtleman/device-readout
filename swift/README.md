# DeviceReadout for Swift

Initial Swift Package Manager foundation. The package declares iOS 16 and macOS 13 deployment targets, but Apple builds and native collectors have not yet been verified or implemented.

`access.observers.target(Entity, id:)` registers an app-owned state target, and `access.observers.publish(entity, snapshot:)` supplies its value without a native getter. App and native handles with the same ID remain distinct. An observed get or first watch value waits for publication within the read timeout, without occupying the native worker. Observed watches deliver each subsequent publication, including equal values, independently of the polling interval. Waiting between those events has no timeout. See [state-observer verification](../docs/verification/2026-11-17-swift-state-observers.md).

Every state watch opens its app input before native polling begins. If the app starts publishing later, the stream stops native polling and delivers those publications in order, including duplicates, without waiting for the polling interval. Late native results and errors are ignored after handoff. If no first snapshot has been delivered, the original first-read deadline is preserved. Normalization still runs on the collection worker and may time out while queued behind an uncooperative native call. See [handoff verification](../docs/verification/2026-11-17-swift-watch-handoff.md).

`observers.current(Entity, target:)` supplies an explicit current selection. An app-owned inventory has no current target until one is supplied; it does not call a native current getter. Passing nil clears the selection and establishes an empty app inventory if none exists. A discovered native handle can also be selected explicitly without changing its namespace. `observers.remove(entity)` retires a bound target or a singleton such as `Entities.ram`, ending its get/watch operations without waiting for a blocked native worker. Old callbacks are ignored after removal. A singleton remains removed in that context; other contexts and entities are unaffected. Registering the same app target ID again returns a fresh handle. Native discovery already in progress cannot recreate a target removed during that query; a later discovery can create a new generation.

The shared schema generates all 46 snapshot types, nullable fields, enums and typed `Entities` constants. `DeviceAccess(collector:)` accepts an explicit collector and provides asynchronous `get(Entity)` on a serial utility queue. `withReadTimeout` returns a new configuration sharing the collector and queue; its default is five seconds. Timeout and caller cancellation complete independently of a blocked collector, and late results are discarded. `collectedAt` is stamped on the worker after normalized fields are prepared. Non-finite scalar numbers and negative duration fields become `nil`; ratios also require 0–1. Non-finite Rect, Insets, Size<Double> and Vector3 components invalidate the entire grouped value. Zero/non-finite quaternions become nil; other quaternions are scaled to unit length while preserving axes and component signs. This does not convert source coordinate frames or infer magnetic north. DisplayMode normalizes its nullable refresh rate independently of pixel size, including within supportedModes. Valid zero/false values, negative screen origins, empty lists and source snapshot values remain intact. See [normalization verification](../docs/verification/2026-11-17-swift-normalization.md).

`observers.failure(entity, error:)` supplies or clears a typed whole-operation error for a singleton, bound target or unbound multi-target kind. Kind errors also apply to list/current. `observers.failureSource(entity)` creates an inert `ObserverFailureSource`; its `publish(error)` and `publish(nil)` update only that provider. `close()` is idempotent and clears only its own active error; deinitialization also releases the slot. Closed sources and sources for retired targets reject publication with `EntityRemoved`. Direct application errors precede provider errors, with exact target scope before kind scope in each group. Multiple active providers at one scope retain their activation order.

Failure invalidates earlier app values while preserving app ownership. Clearing an error does not restore those values, reopen failed streams or clear another provider's error. A new app publication is required; a source that was native before the error can be read natively again. Pending work crossing a failure cannot succeed after an immediate clear or provider close. Error inputs do not request permissions and are separate from permission-status observation. See [observer-failure verification](../docs/verification/2026-11-17-swift-observer-failures.md).

`observers.permission(entity, status:)` supplies `PermissionStatus.granted`, `.denied`, `.notDetermined`, `.restricted`, `.unavailable` or nil. `permissions.check(entity)` reads only this app-observed state. An unbound kind sets the default for its targets; an explicit target status, including nil, overrides that default. App/native namespaces and target generations remain distinct. Configured views share these observations. Permission status does not automatically fail all fields: adapters use whole-operation failures only when authorization prevents the entire operation.

`observers.onPermissionRequest { request in ... }` registers one `PermissionCoordinator` and returns a registration handle that must be retained. The request exposes typed `kind`, optional `targetId` and `observed` namespace. Only an explicit `permissions.request(entity)` invokes it, from a detached utility task; the app dispatches any UI work to its own executor and publishes the resulting status. Returning from the callback does not imply permission was granted. The request completes on the first applicable observed status, including nil; already-granted state returns immediately without invoking a coordinator. Without a coordinator, a non-granted request reports `UnsupportedEntity`. User-response waiting has no read timeout and does not use the native collection queue.

The registration's idempotent `close()` or deinitialization unregisters future requests; already-dispatched requests retain their captured callback. Duplicate registration reports `InvalidConfiguration`, and closing an old handle cannot unregister its replacement. Callback errors preserve `DeviceReadoutError`/cancellation; other errors become `ReadFailed`. Caller cancellation, target removal and context closure finish pending requests without joining callback execution or cancellation handlers. The SDK schedules callback task cancellation away from the caller; app code must cooperate to stop its own work. Context closure releases unused coordinator captures on a background queue independently of held native collection. See [permission verification](../docs/verification/2026-11-17-swift-permissions.md).

`capabilities.get(Entity)` returns immutable `EntityCapabilities(readable: Bool?, watchable: Bool?)`. These describe operation support, separately from permission and individual field availability: false is unavailable and nil is undetermined. The query accepts singletons, unbound multi-target kinds and typed handles. Native queries use `DeviceCollector.capabilities` on the collection worker, bounded by the configured read timeout; its default returns nil for both fields without probing state.

Registered app state targets and observed singletons support get/watch even while permission is denied or cached values have been invalidated. An app-owned kind is available when its inventory is nonempty. Sensor support requires a registered source; a handle alone or an unconnected native sensor does not advertise support. Activity suspension does not remove support. Removed targets return false for both operations; foreign handles and closed contexts remain errors. Known app metadata does not wait for a held worker. Queries do not read snapshots, subscribe sensors or request permissions. Late native values/errors yield to newly registered app support, while timeout and cancellation remain terminal. See [capability verification](../docs/verification/2026-11-17-swift-capabilities.md).

`watch(Entity)` returns a cold `DeviceStream<Snapshot>` for state entities and registered app-owned sensors. For a native state source, iteration performs an immediate read, then serial polling with a default one-second delay after each read. `withPollInterval` creates an independent immutable configuration. Equal values are delivered again with fresh timestamps. Breaking iteration or canceling its task stops that subscription; read failures terminate without retry. The delivery buffer holds at most 2048 pending snapshots; overflow ends collection with `ReadFailed` after already accepted snapshots are consumed. Observed inputs have a separate bounded buffer. Waiting for a poll does not consume the read timeout.

Register an app sensor handle with `observers.target(Entities.pressure, id:)`, then retain the handle returned by `observers.sensorSource(sensor, description:) { session in ... }`. Registration is inert. Each get/watch demand invokes that callback on the collection worker; it receives a typed `SensorObserverSession<Snapshot>` and returns an optional `SensorCleanup` closure. `session.publish(snapshot)` supplies an actual sample, `session.fail(error)` ends that observation, and `session.isStopped` lets app code observe termination. Both setup and cleanup run off the caller's path. Normalization and timestamp assembly also run on the worker; callback publication only buffers supplied data.

Sensor `get` starts a fresh observation and waits for one sample or occurrence within the read timeout. A sample watch includes setup, the first sample and normalization in its initial deadline. Event watches bound registration work but wait indefinitely for the first real occurrence; later event waiting also has no deadline. Each received sample's normalization has its own read limit. StepDetected and SignificantMotion require value true; false or nil source payloads produce `ReadFailed` rather than fabricated events. Equal sensor values are retained, and sensor streams never use the polling interval. Raw samples have a separate 2048-item buffer with explicit overflow and ordered draining of accepted samples.

`describe(sensor)` reads the registered metadata without starting its source, determines kind from the typed entity, normalizes available fields and stamps one collectedAt on the worker. `SensorSamplingRate.platformDefault` is the initial rate. `withSensorSamplingRate(try .hertz(60))` creates an independent configuration; the rate factory rejects zero, negative and non-finite numbers. Only sample watches receive a requested rate through `session.samplingRate`; get and event watches always use platformDefault. A source chooses how to apply the request to its platform; the SDK neither removes samples nor synthesizes a requested cadence.

Retain the `SensorSourceRegistration` while the target is available. Its close/deinitialization retires that app target, ends pending operations and removes it from discovery. A duplicate source is rejected; re-registering the same external ID after removal creates a fresh target generation. Old handles, registrations and stopped sessions cannot modify that replacement. Timeout, cancellation, removal and context closure complete independently of a blocked registration or cleanup; late-created resources are still released once on the worker. Cleanup exceptions are contained. A blocked callback continues to occupy the serial worker until it returns. Native Apple sources and framework lifecycle adapters remain pending. See [sensor-source verification](../docs/verification/2026-11-17-swift-sensor-sources.md).

`observers.sensorActivity(false)` supplies app-owned inactive policy and stops active sensor sessions; `true` resumes each continuing watch with a fresh session. The initial state is active. The SDK does not query foreground/window state, and desktop focus loss alone need not mean inactive. Paused session deadlines are canceled; a resumed sample watch gets a fresh first-value deadline. A sensor get retains its original deadline across the entire wait, including inactivity, and does not start a source while inactive. Late samples and errors from superseded sessions are ignored. State reads and sensor descriptions remain available. See [sensor-activity verification](../docs/verification/2026-11-17-swift-sensor-activity.md).

`list(Entity)` and resource collections such as `storageVolumes.list()` return typed handles. App-owned inventories take precedence over native discovery, including after their last target is removed. Without app ownership, `current(Entity)` uses the collector's explicit current selection; no selection returns nil without choosing the first device. Handles can be reused across configured views of the same context, but a separate `DeviceAccess` rejects them. Repeated discovery preserves identity until removal is detected. Accepted inventory removal or a read-time `EntityRemoved` retires that generation and ends its existing watches, including watches waiting for a long poll interval. Rediscovery creates a fresh handle even if the native ID is reused. Failed, malformed, canceled and timed-out inventories do not erase the last accepted handles.

Collections include `displays`, `viewports`, `cpuCores`, `batteries`, `networkInterfaces`, `wifiConnections`, `cellularSubscriptions`, `telephonyIdentities`, `storageVolumes`, and typed `sensors.list(Entity)`. These are generic discovery APIs, not native platform collectors. Native source IDs appear at the `DeviceCollector` boundary; consumers use the returned entity handles.

`close()` ends the shared context, including configured views, pending reads/discovery and idle state watches. It is idempotent and does not await native work or cleanup. Valid queries after closure fail with `EntityRemoved`; streams created earlier also reject later iteration. `DeviceCollector.close()` is scheduled once on the collection worker after preceding native work returns. Cleanup errors are contained on that worker. Already accepted stream buffers retain the existing drain-before-error behavior.

The worker admits at most 128 waiting reads in addition to any currently executing read. Excess requests fail with `ReadFailed`. Canceled or closed queued requests are skipped before invoking the source. Cleanup bypasses read admission, so a full queue cannot suppress resource release. Canceled queue entries retain their slots until the worker reaches them; a blocked native call can therefore leave the lane saturated until it returns.

There is no bundled Apple collector. A consumer must provide a `DeviceCollector` and register app-owned sensor sources for sensor get/watch/describe; the tests use controlled collectors rather than hardware readings. Autonomous native hotplug/state notifications, native sensor adapters, complete Apple UI/permission/lifecycle adapters, cross-binding normalization parity and external package verification are still required. A timeout, removal, observation failure or context closure does not forcibly interrupt an uncooperative synchronous collector. Sensors without a registered source report `UnsupportedEntity` rather than fabricating samples by polling.

Generate and test from the repository root with Node and Swift available:

```sh
npm run generate
sh tools/test-swift.sh --jobs 2 -Xswiftc -warnings-as-errors
sh tools/test-swift.sh --jobs 2 -c release -Xswiftc -warnings-as-errors
```

`SWIFT_BIN` may point to a specific Swift executable. The test script keeps build/cache artifacts in the ignored `.tools` directory. Root `npm run generate` runs all five language generators; `node tools/generate-swift.mjs` regenerates only Swift.

Swift 5.9.2 / Ubuntu 22.04 under WSL passes all eighty-one current tests in Debug and Release, with compiler warnings treated as errors.
