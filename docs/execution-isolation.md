* Collection, polling and substantial normalization run in an isolated execution context.
* The host sends typed requests and consumes immutable snapshots. No synchronous wait, busy loop, blocking OS call, global setting mutation or unhandled SDK error is allowed on the host path.
* UI-affine state is published by an application-owned observer adapter. The SDK never reads the DOM or displays permission UI as a side effect of get/watch/list.
* A request for permission is handed to the application's coordinator. Completion follows observed permission state, outside the read timeout.
* Native worker threads and browser workers isolate scheduling, not all process crashes. Where process fault isolation is required, use an out-of-process collector. No implementation may claim zero CPU/memory cost or that a thread isolates native process crashes.
* Tests must exercise real isolated execution, include a deliberately blocking collector, and show that the host heartbeat and cancellation still progress.
