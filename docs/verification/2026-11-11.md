## Defects found and corrected

The API 36 emulator's on-change temperature sensor initially emitted approximately −1e30, confirmed in the sensor service output. The adapter now returns null for values below absolute zero. The fixture then changes the emulator's temperature after subscription and verifies a normal 24°C event. This records an observed emulator behavior, not a claim that every Android sensor uses that sentinel.

App-language broadcasts can precede the process resource update. A failing public watch test returned appLanguageTags=[fr-FR] alongside an old currentLanguageTag=en-US and timed out waiting for the final state. The adapter now also observes configuration completion. That main-thread callback only posts work to the background callback lane, which obtains the updated state. The same test passed five consecutive runs after this correction. The SDK does not set application language, recreate Activities or change locale/timezone defaults.

Battery property access uses getLongProperty so unavailable values keep the Long.MIN_VALUE sentinel regardless of the consuming app's target SDK; older-target getIntProperty can report zero instead. Charge, signed current and energy retain their distinct units. Sensor descriptions convert range/resolution into the same units as measurements and do not attach a scalar range to boolean/quaternion values.

TypeScript, C# and Kotlin thermal JSON were checked for consistency: the platform-qualified enum string is preserved. No JSON format change was needed.

## Reproduction and evidence

Run from the repository root:

```powershell
./tools/build-android.ps1 -SdkRoot 'C:/path/to/Android/Sdk'
./tools/test-android-device.ps1 -SdkRoot 'C:/path/to/Android/Sdk' -Serial emulator-5582 -AvdName DeviceReadout_API26 -Mode regionalContracts
```

For API 26 and 36, run `all`, `batteryEvents`, `sensorUnits`, `orientationFrame`, `sensorLifecycle` and `regionalContracts`. This earlier checkpoint used serial emulator-5584 for API 36; the subsequent network checkpoint uses emulator-5586 because 5584 is occupied by an unrelated AVD. Always match the actual project AVD name before testing. Additionally run `timeZoneEvents` and `localeEvents` on API 36. The timezone shell-command fixture requires API 30+; the per-app locale API requires API 33+.

The helper verifies the exact project AVD name before installing or changing fixtures. It checks the explicit instrumentation success status and final code, since adb process success alone does not mean assertions passed. Raw output is in ignored `.tools/DeviceReadout_API<level>-<mode>-results.txt`; JVM results are under `kotlin/core/build/test-results/test` and lint results under `kotlin/android/build/reports`.

AVD data, signing material and CLI state are isolated under `.tools`; adb uses port 5047. Tests do not use the user's normal AVDs. Battery/thermal/timezone fixtures restore native settings; the locale fixture restores the test APK's own setting. Sensor input changes affect only the named disposable project AVD. Actual identifiers are excluded from reports. SDK collection sends no telemetry.

## Remaining acceptance work

Android CPU topology, storage, network/Wi-Fi/current data RAT and eligible restricted identifier adapters remain. HingeAngle, StepCountSinceBoot, StepDetected and SignificantMotion still need adapters; RelativeAltitude/HumanPresence need public-platform availability mapping. ProcessMemory is unavailable rather than filled with Java-heap headroom, which has a different meaning.

Dynamic sensor disconnection/tombstoning code needs actual hotplug validation. Physical sensor accuracy, real battery hardware, foldables, activity-recognition permissions, arm64/32-bit execution, API 28 extended cases and the rest of the supported Android matrix are not established by these virtual x86_64 tests. Clock-preference content-observer delivery and sustained overload also need dedicated coverage.

Browser Window/Generic Sensor/DeviceMotion integrations, Windows remaining collectors/hotplug, Swift/Apple, Flutter/RN, package consumption and complete minimum-version checks remain required. Apple host and target Flutter toolchain are still unavailable locally. Initial state/event ordering and large/malformed response limits in the shared runtimes remain under review. The goal is still active.
