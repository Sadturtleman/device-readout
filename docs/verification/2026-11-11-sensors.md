# Android hinge, step and trigger checkpoint — 2026-11-11

## Scope

Added Android adapters for HingeAngle, StepCountSinceBoot, StepDetected and SignificantMotion. Android now has 35 mapped entities: eighteen state entities and seventeen sensor kinds. This is not a completed Android release or a completed SDK platform matrix.

The application still owns screen, permission and activity observers. SDK collection opens no UI or permission prompt. App-owned `observers.sensorActivity(false/true)` releases/resumes sensor sessions. A callback from a previous session cannot emit into or rearm the new session.

## Mapping and lifecycle contracts

| Entity | Contract |
|---|---|
| HingeAngle | API 30+ native hinge sensor. Values and range/resolution metadata convert degrees to radians. Invalid/nonfinite values or angles outside 0–360 become null. Earlier APIs and absent hardware have no targets. |
| StepCountSinceBoot | Preserve the native boot-based count while activated. Zero and representable large integers remain Long; negative, fractional, nonfinite or values at/above 2^63 become null. No synthetic counter or background counting service. |
| StepDetected | Native step detector special-trigger listener. Every actual 1.0 occurrence emits true, including equal consecutive occurrences. Invalid occurrence payloads fail with ReadFailed. |
| SignificantMotion | Public native one-shot trigger API. Each actual occurrence emits true and rearms for another occurrence. Closing or app inactivity prevents later rearming. Invalid payload/registration refusal produces ReadFailed. |

Step counter/detector collection requires ACTIVITY_RECOGNITION on API 29+. A denied permission returns PermissionDenied without invoking the application's permission coordinator. Metadata/discovery do not request permission. This checkpoint tests the denied/granted branches using an Android service fixture; actual step-hardware permission/app-op transitions remain unverified.

Event watch has no fake initial snapshot or idle timeout; get waits for the next occurrence with its read deadline. Requested Hz applies only to continuous sensors. The step detector and one-shot trigger do not become periodic measurements.

RelativeAltitude and HumanPresence are explicitly unavailable in this standard Android adapter: capabilities false, discovery UnsupportedEntity. There is no matching standard Android sensor meaning; pressure and low-latency off-body detection are not substituted. Future vendor-specific integration would need its own verified contract.

## Execution paths

Discovery, metadata, native registration/cancellation and permission checks run on the collection worker. Ordinary sensor callbacks use their dedicated HandlerThread. Android's public trigger API has no Handler overload and can deliver its callback on the context's main Looper. SDK code in that callback copies one scalar and posts work. Validation, snapshot delivery and rearming occur on a dedicated lane. Rearming and cancellation are serialized, and late callbacks observe the closed subscription.

The production SDK uses public Android APIs only. Test-only Robolectric shadows replace Android's sensor service; their reflection constructs native Sensor/TriggerEvent fixtures, not SDK internals. This establishes SDK behavior under those native inputs, not physical trigger latency, zero resource use, or process crash isolation.

## Automated evidence

`tools/build-android.ps1 -SdkRoot <sdk>` passed with test targetSdk 35: fourteen unchanged common JVM contracts retained their passing Gradle results, eight Android service contracts passed, and AAR/APK assembly plus Android lint passed. Compile SDK remains 35, minimum Android API remains 26. The final build log is `.tools/sensor-adapter-final-build.log`.

The eight Android tests exercise the public SDK against Robolectric 4.16 / Android API 36 fixtures:

- Hinge reads/metadata use radians; invalid sentinel, negative, excessive and NaN values become null; zero and 360° remain valid.
- Step count preserves 0, 42 and 1,099,511,627,776; malformed and overflowing counts become null.
- Denied step counter/detector reads return PermissionDenied without permission requests or sensor registration.
- Step watch has no synthetic initial/idle timeout, retains two true occurrences, and get times out without a new occurrence.
- Malformed step occurrence fails instead of emitting false/null.
- One-shot watch rearms after real occurrences, stops on cancellation and performs no native registration/cancellation on the main Looper.
- App activity input releases the trigger, ignores a delayed callback from the previous session, and resumes a fresh subscription.
- Trigger registration refusal and malformed occurrence produce typed failures and release resources.

Before implementation, public discovery tests failed for missing sensor mappings. The denied-step test initially returned ReadTimeout instead of PermissionDenied; the permission guard corrected it. These are behavioral failures, distinct from initial test-environment setup issues.

Robolectric is test-only. Its framework cache/lock and temporary directory are under `.tools`. The shorter temporary path avoids Windows path-length failures. `-UnitOnly` runs just this adapter suite during development; the final build also runs the common tests, assembly and lint.

## Native emulator evidence

| Scenario | API 26 / target 35 | API 36 hinge fixture / target 35 |
|---|---|---|
| Basic reads, observer-fed display and worker timeout | Passed; main Looper heartbeat 18 ticks | Passed; heartbeat 17 ticks |
| New sensor discovery/capabilities against native inventory | Passed; all four absent | Passed; hinge present, step/trigger types absent |
| Existing sensor unit conversion | Passed | Passed |
| Actual Activity inactivity/resume | Passed | Passed |
| Hinge native get/watch, 90°→180° | Not available before API 30 | Passed; corrected fixture passed three consecutive runs |

Every reported native pass contains both `deviceReadoutStatus=passed` and `INSTRUMENTATION_CODE: -1`. Reports live under `.tools/DeviceReadout_API26-*-results.txt` and `.tools/DeviceReadout_API36_Hinge-*-results.txt`.

The UI heartbeat case intentionally runs a 500 ms cancellation-insensitive collector while a caller's 100 ms read deadline expires. The caller returned before 450 ms and the main Looper kept running. This is representative execution-isolation evidence, not a claim that sensor/native code can never fail or consume resources.

The separate `-HingeFixture` AVD exposes a Goldfish hinge sensor. Its native maximum is 360°, even though the emulator fixture's hinge motion range is configured to 180°; metadata assertions use the actual native range. On activation, Goldfish can first return `-1e30` or its previous 180° state before the requested 90°. The final fixture records those native values and keeps a native observer active until 90° is reached before SDK assertions. Final traces were `[180.0, 90.0, 180.0]`. SDK get returns π/2 and watch receives π from the native change while configured poll interval is 30 seconds. The helper restores the original 180° angle. Invalid initial-value conversion is separately tested through the SDK; the production collector does not retry or filter that first invalid measurement.

All AVD mutations were confined to exact-name-checked project devices. Both project AVDs were stopped after verification. The unrelated Medium_Phone AVD and shared adb discovery were left intact.

## Remaining evidence

Physical hinge/step/trigger hardware, actual activity-recognition permission/app-op changes, trigger rearm failures on hardware, dynamic sensor hotplug and remaining Android versions/consumer targets are still unverified. The step/trigger emulation fixtures are not evidence that the installed AVD contains those sensors. No Apple, Flutter, React Native, browser or Windows verification was rerun for these Android-only changes. The full 46-entity, multi-platform objective remains active.
