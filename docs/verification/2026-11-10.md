The browser blocked-collector fixture busy-loops for 2 seconds. The read rejects at the configured 150ms deadline while the host timer makes 30 ticks. The Node fixture blocks for 1500ms with a 120ms deadline. The .NET and JVM fixtures block for 800ms and return their respective 90ms/80ms deadline failures without waiting for the collector to finish.

The real Windows run returned 51,539,607,552 installed RAM bytes and 51,317,346,304 kernel-accessible bytes. Inside the restricted sandbox, firmware installed-memory access returned null while kernel/available memory remained readable. This verifies the distinction between partial field unavailability and whole-entity failure. Native discovery found three volumes via GUID enumeration and 84 network interfaces; no physical resource was changed for these tests.

The tests use read-only OS queries, local servers and independent browser profiles. The source tree is not published, no remote repository is configured, and no app-user telemetry is sent.

The Android fixture blocks its collector for 500ms while the call is made from `Dispatchers.Main`. The 100ms read deadline returns without waiting for that collector, and the main Looper runs 17 heartbeat ticks. Native results include Linux kernel 4.4.124+, X64 host/process architecture, and 1,567,379,456 kernel-accessible RAM bytes. Physical/advertised RAM remain null on API 28. Android ID is read twice for stability within the test and never included in output. The test helper checks both the instrumentation status and final code; adb success alone is insufficient.

API 26 returns 2,096,115,712 kernel-accessible bytes and no advertised value. API 36 returns 2,067,742,720 kernel-accessible bytes and 4,000,000,000 advertised bytes. These distinct results verify that the collector does not substitute one memory meaning for another. All three runs use virtual x86_64 devices; arm64 hardware and 32-bit process behavior remain unverified.

The queue-pressure JVM test first reproduced a subscription leak: cancellation tried to enqueue cleanup behind a full collection queue, leaving the subscription active until context closure. Cleanup now has a separate pending set drained on the collection thread after work completes, including when its wake-up task cannot enter the full queue. The regression test passes without closing the context to trigger cleanup.

Not verified: full Windows/Android feature coverage or supported-OS-version matrix, physical Android hardware, actual Apple hosts, Flutter/RN bindings, physical sensors, real hidden/visible browser lifecycle, Firefox/Safari, packaging/minimum-version installation, sustained load/memory limits. Sensor lifecycle currently uses controlled collector fixtures; this must not be reported as physical sensor validation.

Results are `.tools/DeviceReadout_API26-results.txt` and `.tools/DeviceReadout_API36-results.txt`.
