# Android Wi-Fi·셀룰러 구현 검증 — 2026-11-11

WifiConnection과 CellularSubscription의 Android 수집기를 추가했다. Android 구현 범위는 상태 엔티티 18개와 센서 13종, 총 31개다. 전체 SDK 출시 기준을 모두 충족했다는 의미는 아니다. 필드별 실제 매핑은 [수집기 문서](../collector-mappings.md)에 기록했다.

## 실행 환경과 결과

프로젝트 전용 x86_64 AVD인 DeviceReadout_API26과 DeviceReadout_API36을 사용했다. Kotlin 2.1.21, coroutines 1.10.2, Gradle 8.9, AGP 8.7.3, compileSdk 35이며 최소 OS는 API 26이다. 개발 중 targetSdk 26도 실행했으며, 아래 최종 검증 조합은 **targetSdk 35 앱**으로 통과했다. OS 버전과 앱의 targetSdk를 구분한다.

| 검증 모드 | API 26 | API 36 | 확인한 동작 |
|---|---|---|---|
| all | 통과 | 통과 | 기본 엔티티 조회, 센서, 앱이 전달한 화면 상태, 메인 Looper 응답성과 조회 제한 시간 |
| wifiContracts | 통과 | 통과 | 연결 탐색·기본 대상·필드 단위 변환·watch·권한 요청 미발생 |
| wifiAuthorized | 통과 | 통과 | 위치 권한을 허용한 테스트 앱에서 SSID/BSSID 조회 |
| wifiEvents | 통과 | 통과 | 실제 연결 해제, 기존 watch의 EntityRemoved, 재연결 후 이전 핸들 무효 유지 |
| cellularDenied | 통과 | 통과 | 실제 전화 상태 권한 미허용을 PermissionDenied로 반환 |

| cellularContracts | 통과 | 통과 | 활성 구독 탐색·현재 데이터 구독·메타데이터·데이터 RAT·watch |
| batteryEvents | 통과 | 통과 | 배터리·전원 알림; API 36 열 상태 알림 포함 |

통과한 조합은 27개다. AAR·테스트 APK 빌드와 Android lint도 통과했다. 변경되지 않은 Kotlin core의 14개 테스트 결과는 Gradle의 최신 상태 검사로 유지됐다. 이전 브라우저·.NET 검증을 이번 Android 변경 때문에 다시 실행하지는 않았다.

두 AVD의 all 모드에서는 취소를 무시하는 수집기가 500ms 동안 실행되는 상황에 100ms 조회 제한을 적용했다. 호출은 450ms 이내에 ReadTimeout으로 끝났고 메인 Looper heartbeat가 각각 18회 진행했다. 이는 UI 스케줄링과 제한 시간 분리를 검증한 결과이며, CPU·메모리 사용이 없거나 네이티브 프로세스 충돌까지 격리한다는 주장은 아니다.

## Wi-Fi 계약

연결별 타입 핸들로 get/watch를 호출한다. current는 앱의 기본 Network가 Wi-Fi인 경우에만 해당 연결을 고른다. SDK는 스캔, 연결 변경, 위치 권한 요청을 수행하지 않는다.

API 36에서는 위치 권한 미허용 시 SSID/BSSID가 null, 허용 시 값이 반환됐다. API 26 이미지에서는 미허용 상태에서도 OS가 해당 값을 노출했다. SDK가 플랫폼별 권한 정책을 임의로 동일하게 만들지는 않는다. 보고서와 테스트 로그에는 실제 SSID/BSSID 대신 값의 존재 여부만 기록했다.

실제 Wi-Fi를 해제한 뒤 기존 watch가 30초 폴링을 기다리지 않고 EntityRemoved로 종료됐다. 다시 연결한 대상은 읽을 수 있었고 이전 핸들은 계속 무효였다. API 26의 연결 변경은 테스트 APK의 WifiManager로, API 36은 프로젝트 AVD의 shell 명령으로 수행했다. SDK 수집기에는 이 변경 코드가 없다.

단위 검증 중 기존 WifiManager 조회는 11 Mbps, 연결별 NetworkCapabilities는 1 Mbps를 반환하는 사례를 관찰했다. SDK는 후자의 값을 1,000,000 bit/s로 올바르게 변환했다. 검증 기준을 해당 연결의 OS 원시 값으로 맞추고 조회 전후의 값 변화도 허용했다. 서로 다른 API의 갱신 시점을 동일하다고 가정하지 않는다. [Android의 연결별 WifiInfo 조회 계약](https://developer.android.com/reference/android/net/wifi/WifiManager#getConnectionInfo())을 따른다.

## 셀룰러 계약과 수정한 오류

활성 구독별 슬롯, 통신사, 국가, MCC/MNC, 데이터 RAT, 로밍 상태를 조회한다. API 26 AVD의 데이터 RAT 13은 Lte, API 36의 20은 Nr로 반환됐다. 표시용 5G 아이콘이나 음성 연결 기술은 사용하지 않았고 NR을 NSA/SA로 구분하지 않았다. 식별 번호·전화번호·ICCID는 이 엔티티에서 수집하지 않는다.

처음에는 OS가 권한 거부 시 예외를 던질 것으로 기대했지만 API 36은 빈 목록을 반환했다. API 26에서도 앱 접근 작업이 차단되면 빈 목록과 0개를 반환하는 경우를 재현했다. 빈 목록을 대상 제거로 처리하기 전에 네이티브 접근 검사와 기존 OS용 권한·app-op 검사를 수행하도록 수정했다. 이제 두 경우 모두 PermissionDenied를 반환하며 SDK가 권한 UI를 열지 않는다. 이 동작 차이는 [Android 구독 서비스의 접근 검사](https://android.googlesource.com/platform/frameworks/opt/telephony/+/refs/heads/main/src/java/com/android/internal/telephony/subscription/SubscriptionManagerService.java)에서도 확인할 수 있다.

네이티브 데이터·서비스 상태 알림과 구독 변경 알림을 연결했다. API 26에서는 폴링을 30초로 설정하고 15초 제한 안에서 실제 로밍 왕복 전환을 수신했다. API 36의 동일 시험은 모뎀 콘솔에 roaming을 설정해도 Android의 isNetworkRoaming이 계속 false였다. SDK도 false를 전달했고 최종 직접 조회도 false였다. 해당 실패를 통과로 바꾸지 않았으며 **API 36 로밍 전환 검증은 남아 있다**. 콘솔 상태와 Android 서비스 상태가 같다고 가정하지 않는다. 사용한 명령은 [공식 에뮬레이터 콘솔 명령](https://developer.android.com/studio/run/emulator-console)에 설명돼 있다.

## 실행 경로와 테스트 복원

화면·권한·앱 활동 상태는 기존 앱 소유 옵저버 입력을 유지한다. 새 수집기의 서비스 조회·정규화는 수집 worker에서, 네이티브 알림은 별도 HandlerThread에서 처리한다. 셀룰러의 구형 listener도 자체 Looper에서 생성한다. Wi-Fi 일회 조회가 사용하는 임시 callback은 종료·취소 시 해제한다. get/watch가 앱의 권한 coordinator를 호출하지 않는 것도 확인했다.

권한 준비 도구는 테스트 앱의 checkSelfPermission으로 상태를 읽는다. API 26 dumpsys가 미허용 항목을 생략하는 문제를 피하기 위한 것이다. 전화 상태 app-op은 API 26의 패키지 모드와 최신 Android의 UID 모드를 각각 보존한다. 허용 시험은 둘 다 allow, 제한 시험은 ignore로 설정하고 원래 상태로 복원한다. 현대 Android의 UID allow가 패키지 ignore보다 우선해 제한 시험이 실제로는 제한되지 않았던 문제도 이 도구에서 수정했다.

마지막 직접 확인에서 두 AVD의 coarse/fine 위치 권한과 READ_PHONE_STATE는 모두 원래의 미허용 상태였다. Wi-Fi는 enabled, 모뎀 voice/data는 home이었다. API 26의 원래 전화 app-op allow와 API 36의 패키지 allow/UID ignore도 복원됐다. 테스트 도구는 이름을 확인한 프로젝트 AVD와 자체 테스트 APK만 변경한다. 별도로 실행 중인 사용자 AVD는 건드리지 않는다.

검증 종료 후 이름을 재확인한 프로젝트 AVD 두 개만 종료했다. adb 목록에서 두 장치가 사라졌고 기존 사용자 AVD는 계속 연결된 상태임을 확인했다. 공유 adb 서버는 종료하지 않았다.

## 재현

```powershell
./tools/build-android.ps1 -SdkRoot 'C:/Users/rugsn/AppData/Local/Android/Sdk' -TestTargetSdk 35
./tools/test-android-device.ps1 -SdkRoot 'C:/Users/rugsn/AppData/Local/Android/Sdk' -Serial emulator-5582 -AvdName DeviceReadout_API26 -Mode wifiEvents
./tools/test-android-device.ps1 -SdkRoot 'C:/Users/rugsn/AppData/Local/Android/Sdk' -Serial emulator-5586 -AvdName DeviceReadout_API36 -Mode cellularRestricted
```

기본 빌드 대상은 targetSdk 35다. 구형 앱 정책 확인은 -TestTargetSdk 26으로 별도 빌드한다. adb의 종료 코드만으로 성공을 판정하지 않고 deviceReadoutStatus=passed와 INSTRUMENTATION_CODE: -1을 함께 요구한다. 최종 원시 결과는 `.tools/DeviceReadout_API<level>-<mode>-results.txt`에 남는다. 각 결과의 targetSdk도 확인해야 한다.

## 남은 검증

물리 Wi-Fi, 동시 다중 연결과 VPN 경로, 위치 스위치 변화, 보안 방식 전체, 29–30 및 31–34 API 구간, 다중 SIM·eSIM 전환, carrier/system 특권, SIM 제거·재등장, 극히 빠른 대상 ID 재사용은 아직 입증하지 않았다. API 36 로밍 전환에는 Android 상태를 실제로 바꾸는 별도 장치나 fixture가 필요하다. 앱이 SDK callback 수명 중 권한을 잃는 전체 시나리오와 초기 조회·동시 이벤트 순서도 추가 검증 대상이다.

Swift/Apple, Flutter, RN 및 브라우저·Windows의 남은 구현도 계속 필요하다. 전체 범위와 다음 작업은 [구현 현황](../implementation-status.md)을 따른다.
