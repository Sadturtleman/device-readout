# Implemented collector mappings

This file records actual implementation, separately from the full design scope. Unmentioned fields are nullable and currently unavailable from these adapters. It does not declare the platform release complete.

## Swift Foundation

`DeviceAccess()` connects the following initial native mappings. Swift 5.9.2 Linux Debug/Release and separate SwiftPM consumers are verified; iOS/macOS builds and physical execution remain pending. See the [native Foundation checkpoint](verification/2026-11-19-swift-native-foundation.md).

| Entity | Native mapping |
|---|---|
| Runtime | Compile-target process architecture and native pointer width. Host architecture and supported ABIs remain nil. |
| TimeZone | Foundation system identifier, one resolved rule set and one instant for offset/DST. Valid fixed IANA UTC/GMT names supplement the region list. Windows ID remains nil. System-time-zone notification invalidations supplement serial polling. |

Optional native invalidations register and clean up on the collection worker. App-owned state takes over without retaining native observation; held setup/cleanup does not join the caller. Other native entities remain unsupported while existing app observers and sensors retain their contracts.

The worker uses network `change`, `online`, `offline` and `languagechange` events. Other implemented state reads use polling. Window-owned screen, motion, orientation and permission state is supplied through the explicit app-owned adapters below. Generic Sensor and other sensor adapters remain pending.

The explicit `observeWebViewport(access, window)` application adapter adds Viewport. Its initial callback and Window/VisualViewport resize listeners publish layout size from innerWidth/innerHeight, visual size from VisualViewport.width/height and visual scale from VisualViewport.scale. Sizes are CSS pixels; layout size includes scrollbars. Safe-area and text-scale fields remain null. SDK get/watch read this observed state without accessing Window. Every event is retained, including equal values. Multiple calls create separate context-local targets. Closing the observation or receiving pagehide retires its target; restoration/reconnection requires a new observation. Cross-origin access denial is PermissionDenied before registration. See the [viewport verification checkpoint](verification/2026-11-11-web-viewport.md).

`observeWebDisplays(access, window, details, {permission})` adds Display from app-supplied ScreenDetails and optional native PermissionStatus. It maps label, primary/internal flags, logical/work-area bounds, per-screen scale factor and color depth; pixel size is rounded logical size × that screen's scale. Current-screen orientation/angle use the app window's ScreenOrientation; non-current orientation stays null because Chromium's detailed-screen orientation can be window-scoped. Other Display fields remain null. Native screen objects own context-local handles, independent of label; addition, removal, current selection and native property changes update through observers. The adapter does not call getScreenDetails, query/request permissions, move windows or alter screens. Native PermissionStatus changes gate reads/discovery, while whole observer failures invalidate cached snapshots and terminate streams. See [display verification](verification/2026-11-11-web-displays.md) for native virtual-monitor evidence and physical-device limitations.

`observeWebMotion(access, window)` adds four context-local event-source targets. It never requests permissions or queries screen orientation. Native subscriptions follow get/watch demand and are released on cancellation/inactivity; worker normalization produces the public snapshots. Metadata exposes kind only because DeviceMotion provides no physical sensor inventory/metadata. Its fixed browser event cadence is preserved when a frequency is requested.

| Motion entity | Native event mapping |
|---|---|
| Accelerometer | accelerationIncludingGravity x/y/z, m/s² |
| LinearAcceleration | acceleration x/y/z, m/s² |
| Gravity | accelerationIncludingGravity minus acceleration from the same event, m/s² |
| Gyroscope | rotationRate alpha/beta/gamma → X/Y/Z, multiplied by π/180 to rad/s |

Every vector requires all three finite components. The current rotationRate getter mapping differs from the alpha/beta/gamma Euler-angle order used for device orientation. It was checked against actual native virtual-gyroscope readings. [DeviceMotion rotation-rate interface](https://www.w3.org/TR/orientation-event/#devicemotioneventrotationrate), [Chromium motion event pump](https://raw.githubusercontent.com/chromium/chromium/main/third_party/blink/renderer/modules/device_orientation/device_motion_event_pump.cc).

`observeWebOrientation(access, source)` supplies RelativeOrientation from deviceorientation with absolute=false and AbsoluteOrientation from deviceorientationabsolute with absolute=true. If the dedicated absolute event is absent, the absolute target uses absolute=true samples from the general event. Mismatched frames or missing/nonfinite angles produce a null value. Native intrinsic Z–X′–Y″ angles become named x/y/z/w device-to-reference quaternions. Relative session reference and absolute east/magnetic-north/up reference are preserved; no screen correction or initial-pose rebasing is applied. Metadata is kind only. The adapter preserves native cadence and follows the same source/activity cleanup contract as motion. See [orientation verification](verification/2026-11-11-web-orientation.md).

## Flutter application viewport observer

`FlutterViewportObserver.attach(access, view: ...)` observes one app-selected FlutterView through WidgetsBinding. It maps physicalSize/devicePixelRatio to Viewport.size, viewPadding/devicePixelRatio to safeAreaInsets, and the system PlatformDispatcher.textScaleFactor to textScaleFactor. Visual viewport size/scale remain null; keyboard insets are not substituted for a visual-viewport API. Initial and framework event callbacks copy the values, while ordinary SDK reads never query Flutter UI properties. Handles follow view lifetime, removal and exact registered-object identity, including ID reuse. Worker normalization, typed failure invalidation and explicit app current-target selection use the common Dart observer runtime. Ten combined screen engine checks and five actual Windows Release scenarios pass. Other platforms and physical lifecycle evidence remain pending. See [Flutter screen verification](verification/2026-11-11-flutter-screens.md).

`FlutterDisplayObserver.attach(access)` owns the Flutter-exposed Display inventory; `selectView` explicitly chooses the registered view whose display becomes current. PixelSize and scaleFactor come from valid Display.size/devicePixelRatio. Windows currentMode uses the pinned engine's EnumDisplaySettings current-settings rate; unspecified 0/1 and unknown values remain null. Other engines' mode mappings remain pending. No physical DPI, monitor origin, maximum rate or primary status is inferred. Independent getter failures are nullable; inventory failure invalidates the collection. Framework Display object replacement retains live IDs, while observed disappearance permanently retires handles. The actual Windows fixture corroborates two monitors and a 5120×2160, 1.5-scale, 144Hz selected monitor after a fresh post-parenting metrics notification. Initial hidden-window association timing is a documented Flutter source limitation.

These state collectors use serial polling. Power and Battery additionally register native power-setting callbacks, which defer collection to the worker. Volume discovery detects disappeared GUIDs and tombstones their old handles; a later appearance gets a new context-local generation. Relative capacities are not converted into physical energy/power, native unknown sentinels remain null, and battery critical-drain flags do not become health diagnoses. See [battery fields](verification/2026-11-11-windows-battery.md) and [power events](verification/2026-11-11-windows-power-events.md) for evidence and limitations.

Battery device-interface notifications are registered before the first inventory and retained until context closure. Removal versions retire idle handles and reject in-flight results even after same-path/same-tag reappearance; stable rediscovery creates new handles. See [battery interface lifetime](verification/2026-11-11-windows-battery-hotplug.md). Its ReportUpdated callbacks defer report reads to the worker, and absence is reported as present=false without retiring the logical endpoint. Individual Battery watches also use overlapped native status waits with tag-pinned power-state/capacity conditions. Returned status values are preserved in deferred snapshots, and polling remains active for other fields. Their dedicated background lanes cancel and drain completion before freeing native buffers; consumer closure does not join those waits. See [individual status observation](verification/2026-11-11-windows-battery-status.md). Volume hotplug and rapid network adapter reuse still need corresponding coverage. Remaining Windows event supplementation, physical battery/driver evidence, remaining Wi-Fi fields/current data RAT and remaining sensor families are pending. The Windows package is not release-ready.

Wi-Fi collection uses profile APIs and the separate RSSI query without scanning, reading gated BSSID information or implicitly requesting permission. Authentication mapping preserves current PSK/EAP/SAE/OWE and WPA3 enterprise meanings; Open80211 requires the cipher value to distinguish Open from WEP. Failed inventories preserve existing handles, while observed disappearance or network-ID replacement retires them. App-owned permission status and blocking failures remain separate inputs. Actual active discovery is empty on this host; nonempty fields and transitions currently use controlled native inputs. Actual WLAN absent-interface reads and client cleanup agree with an independent C probe. See [profile verification](verification/2026-11-11-windows-wifi.md) and [signal verification](verification/2026-11-11-windows-wifi-signal.md) for mappings, deadlines and remaining physical evidence.

Network discovery permanently retires handles after observed absence, including removal found by get; failed or malformed inventories do not erase targets. All active streams for an observed removed generation terminate. Three context-owned IP Helper registrations start before the first inventory and persist until context closure. Their callbacks only enqueue reads; native cancellation runs on the worker without callback locks. Protocol-level deletions are not interpreted as adapter removal. Real Windows reads and registration/acknowledgement/cancellation pass, while transition and same-ID rediscovery cases use controlled OS inputs. Rapid cycles between inventories, reliable adapter-level PnP history and physical transitions remain pending. See [network verification](verification/2026-11-11-windows-network.md).

Network routes preserve destination prefixes and scoped IPv6 gateways; unspecified next-hop addresses become null gateways. Failed/malformed route data or observed LUID changes leave Routes null, while successful empty results remain empty. Native buffers are bounded and released on the worker. IPv6 MTU is used when the existing IPv4 path is unavailable; zero is preserved and negative values remain null. Actual route counts and native layout agree with a separate C query, while IPv6-only MTU uses controlled OS properties. See [route and MTU verification](verification/2026-11-11-windows-network-fields.md) for evidence and remaining compartment/hardware limits.

CPU topology, availability and clock reads run on the collection worker. Record reordering preserves target handles, failed inventories do not erase targets, and observed removal retires them. Actual x64 native counts agree with an independent CIM query. Live availability reflects affinity, default CPU sets and reservation eligibility; it does not aggregate explicit per-thread overrides. Unknown/racing mappings leave only availability null. Native child tests cover affinity/default-set/Job changes and unchanged settings after SDK reads. Multi-group availability, wide WOW64 masks, actual exclusive reservations, WOW64 targets, multi-group/sparse clock mapping and actual CPU hotplug still need work. See [CPU topology verification](verification/2026-11-11-windows-cpu.md) and [live availability verification](verification/2026-11-11-windows-cpu-availability.md).

Publisher identity preserves the native app-context scope: unpackaged Win32 apps and packaged apps without a publisher ID share the native ID. It is not a permanent cross-platform hardware identifier. Unknown native sources become null without discarding a readable ID; no ID is synthesized. Actual normal-user reads and worker cleanup pass, while the restricted-process native API returns a typed ReadFailed. See [identity verification](verification/2026-11-11-windows-publisher-identity.md) for exact evidence and unverified persistence/publisher cases.

NetworkPath maps known native None/LocalAccess/ConstrainedInternetAccess/InternetAccess to local connection state and OS internet classification; unknown levels remain null. Native unrestricted cost is unmetered, fixed/variable cost is metered, and unknown cost stays null. Connectivity and cost failures are independent. Limited access does not prove a captive portal or constrained-data mode. Transport sets and the remaining path fields are not inferred. Watch owns a native status registration, with E_NOTIMPL polling fallback and typed registration failures. Actual reads agree with an independent PowerShell WinRT projection; registration/removal and controlled transitions pass. Real network changes, virtual/explicitly bound routes and remaining fields need work. See [preferred path verification](verification/2026-11-11-windows-connectivity.md).

Native calls run on one bounded background collection lane per context, except the explicitly separate battery-status wait lanes. A stuck native collection call cannot block the caller's deadline, but subsequent operations on that lane can time out until it returns. This implementation does not claim process-crash isolation. Windows UI and permission data enter through the same observer contracts as the common SDK.

NetworkPerformance re-queries the preferred profile and plan for every get/poll/deferred native notification. Missing rates stay null and valid zero stays zero; one rate failure preserves the other, and both failures or plan acquisition failure are typed whole-query errors. Concurrent path/performance subscriptions enqueue their own read functions and release independently. Actual native reads return null rates on this host, corroborated by an independent WinRT projection. Non-null rates and changes currently use controlled native inputs. See [performance verification](verification/2026-11-11-windows-network-performance.md) for ABI, lifetime and remaining carrier/route evidence.

Collection is dispatched by the Kotlin runtime. Construction does not query services or start a thread. Display, permission and activity state are supplied by app-owned observers; no Activity/Window access or permission prompt is performed. Power, battery, regional, network, storage and sensor callbacks have dedicated HandlerThreads. Power is event driven; battery uses events plus polling because instantaneous current/energy are not fully covered by broadcasts. Other initial state collectors use polling. Model fields without a native mapping remain null, including physical RAM and current free RAM. Unknown ABI members null the whole set. Build.UNKNOWN becomes null, and supported ABI ordering is never substituted for the running process architecture.

CPU targets distinguish present processors from online processors and from the number available to the process. CPU current() is null because a multithreaded process has no single current processor. Native indices plus sysfs device/inode identity retain removal tombstones; online/offline alone does not create a new target. Negative topology IDs and unavailable files become null. Aggregate core/package counts require complete topology data; exposed topology is what the guest OS reports, not the host machine's hardware layout. CPU reads are polled. The native driver's current and maximum frequencies are not clamped to each other.

Storage current() resolves the volume containing applicationInfo.dataDir. Discovery includes that private view and mounted shared views, which can share the same backing device; callers must not sum them as unique physical disks. API 30+ uses StorageVolume.directory. Earlier APIs use the primary directory getter or match actual mount points through the public getStorageVolume API, without creating app directories. A volume with unavailable path/statistics retains readable metadata. fileSystem describes the visible mount (for example fuse), not a guessed backing filesystem. totalBytesForCaller, encryption, case sensitivity and important/opportunistic capacity remain null; cache quota is not substituted for total app capacity. Allocation availability is read on the worker, without allocateBytes or storage UI.

Storage broadcasts retire removed/unmounted targets using the supplied native volume. watch also polls because free capacity changes lack complete events. Re-discovery creates a fresh handle after observed removal or a changed mount identity; mounted-state transitions and callback reads run off the UI thread. Real virtual-disk unmount/remount tests pass on API 26/36. Physical disks, fast unobserved identity reuse and CPU hotplug remain unverified; mount IDs/inodes alone are not permanent generation guarantees.

Locale uses native locale broadcasts, a clock-preference ContentObserver and a configuration observer. The configuration callback only schedules background work, allowing the post-Resources-update state to arrive after an earlier locale broadcast. Locale/timezone polling remains for app-local overrides and DST transitions without complete native event coverage. API 26/27 measurementSystem and pre-33 explicit appLanguageTags are null. A known empty API 33+ app locale list means no explicit app override. System locales and preferred app locale order are not substituted for one another. ProcessMemory is currently unavailable on Android: Java Runtime heap capacity is not the design's process-wide allocation capacity.

Sensor callbacks normalize native units and quaternion components without following display rotation. Sensor range/resolution metadata uses the same SDK units; boolean event/proximity and quaternion fields do not borrow an unrelated scalar range. PlatformDefault requests SENSOR_DELAY_NORMAL; a requested Hz applies only to continuous reporting sensors. Core lifecycle input releases subscriptions on inactivity and re-registers on resume. Dynamic inventory generations and disconnect callbacks tombstone old targets; actual hotplug remains unverified. RelativeAltitude and HumanPresence have no mapping to the standard Android sensor types: capabilities are false and discovery returns UnsupportedEntity. Pressure and low-latency off-body detection are not substituted for these meanings.

Step counter/detector collection requires ACTIVITY_RECOGNITION on API 29+, supplied by the host app; collection never requests it. Native boot-based count is preserved, including zero. Inactive sessions release the native listener, so the SDK does not promise continuous background step counting. Event sensors emit only actual true occurrences, have no synthetic initial value or idle watch deadline, and reject malformed occurrence payloads with ReadFailed. SignificantMotion uses the public trigger API. Android may deliver its initial callback on the context's main Looper; that callback only copies one scalar and posts work. Validation, delivery and rearming run on a dedicated lane, and cancellation prevents later rearming. No hidden Android API is used in SDK production code.

Battery getLongProperty preserves Long.MIN_VALUE as unavailable; older-target getIntProperty can misleadingly return zero. Charge/current/energy are kept in their distinct units. No P=VI or energy/capacity inference is used. Android thermal enums serialize with their platform-qualified names, consistently with the TypeScript and C# contracts.

State observers enqueue deferred reads through DeviceCollector.observeReads. Power, battery, regional and interface notifications request a fresh read on the collection worker with the configured deadline. NetworkPath/NetworkPerformance capture the native callback's network/capability/link payload instead: re-querying after onLost was reproduced returning stale connected state even though the native default network was later absent. The captured values are mapped on the worker; data-saver status is also read there. No NetworkCallback performs a synchronous follow-up OS query. Equal values remain observable, and the SDK does not reconstruct transitions the OS never delivered. NetworkInterface supplements notifications with polling for unmanaged/loopback interfaces. Sensors still emit actual samples through observe.

NetworkPath describes Android's app-default Network, not an individual socket's explicitly selected/bound route. Configured IPv4/IPv6 addresses and DNS are not proof that an external server is reachable. Internet validation is the OS capability, not a probe by this SDK. Metered is not copied into expensive/constrained. Any unrecognized transport bit makes the entire transport set null. Missing default network produces Disconnected/empty transports and null path-specific bandwidth. Android's redacted MAC 02:00:00:00:00:00 is null. Interface type is never guessed from its name; an unavailable/unknown operstate is null.

Native interface enumeration needs the host's INTERNET declaration: an API 36 test without it returned an empty OS inventory despite a connected path. The adapter now distinguishes this permission failure. ACCESS_NETWORK_STATE is required for the path/performance and for optional interface network metadata. Missing network-state permission leaves interface DNS/routes/type unavailable while Java interface data remains readable with INTERNET. Discovery/current handles are context-local and retain removal tombstones; a new OS index gets a new handle. Real virtual-interface removal/replacement passed on API 26/36; physical hotplug and extremely rapid churn remain unverified.

Android ID retains Android's signing-key/user/device scope and reset conditions. Its explicitly requested collector has a local HardwareIds lint suppression documenting why that specific access exists; this is not a claim that Android ID is universal or permanent.

HardwareSerial and TelephonyIdentity are explicitly requested reads. Android enforces identifier access; the SDK does not reduce that policy to a READ_PHONE_STATE precheck or try another identifier when it fails. Modern ordinary apps can receive PermissionDenied despite that permission. A legacy consumer can instead receive native UNKNOWN/null, preserved as null. Serial watches poll. Telephony discovery is independent of active subscriptions and returns logical slots in ascending index order; current() is null because no single identity slot is inherently current. SIM presence is not used to decide whether a modem can expose an IMEI.

Telephony identifier fields are independent: a readable IMEI survives an unavailable/denied MEID, and vice versa. If no identifier value is readable and a native call reports permission denial, the whole read is PermissionDenied. Two unsupported native APIs produce UnsupportedEntity; successful native nulls remain null. No UUID, ANDROID_ID, SIM identifier or deprecated getDeviceId fallback is used. Target validity is checked again after the field reads. API 30+ watch receives protected multi-SIM configuration broadcasts on a dedicated HandlerThread and retains the event's removed-slot count before deferring a worker read; polling supplements notifications. Observed removed targets never rebind after a slot returns. Unobserved transitions while no watch is attached and physical multi-modem behavior still need verification.

Wi-Fi targets represent connections, not adapters. current() selects only a Wi-Fi connection that is itself the app's default Network; a VPN default does not pick an arbitrary underlying connection. API 31+ reads use a short-lived NetworkCallback with FLAG_INCLUDE_LOCATION_INFO so the OS can apply the caller's actual location permission and location-switch policy. API 29–30 uses WifiInfo from NetworkCapabilities when available; the legacy WifiManager getter is used only for an unambiguous sole Wi-Fi connection. Legacy reads require ACCESS_WIFI_STATE, and discovery requires ACCESS_NETWORK_STATE. Redacted SSID/BSSID markers become null. Before API 31, negotiated security is null; scan capabilities are not substituted. Before API 29, separate receive/transmit speeds remain null. Unknown security values, including OSEN which has no common enum member, become null. watch combines native callbacks with serial polling for fields without complete notifications. Observed disconnect permanently retires the target. No scans or connection changes occur in SDK code.

Cellular current() selects the active data subscription on API 30+, or the default data subscription on older APIs. MCC/MNC preserve leading zeros using native strings; the selected subscription's SIM operator string is the legacy fallback. radioTechnology uses the actual data network type, never voice type, display overrides or allowed-network bitmasks. Public NR remains Nr; NSA/SA is not inferred. Slot numbers and native subscription IDs are not exposed as permanent device identities. Metadata changes use subscription listeners; radio/service state uses TelephonyCallback on API 31+ and a Looper-owned PhoneStateListener earlier. Callback values are captured and mapped on the worker; polling supplements incomplete notifications. Phone-state access can come from READ_PHONE_STATE or native carrier/system privileges. Empty native lists receive an access check before retiring targets because denied access can also produce empty output. Individual unavailable radio fields remain null. The SDK neither requests these rights nor changes the radio.

Wi-Fi and cellular callbacks use dedicated HandlerThreads, with no Activity/Window access. Wi-Fi get cancellation/deadline unregisters its temporary callback. Connection and subscription handles are context-local; observed removals are tombstoned. Physical multi-network/multi-SIM cases, carrier privileges and rapid unobserved identity reuse still need verification.

NetworkCapabilities and the legacy WifiManager getter can refresh link statistics at different times. Modern Wi-Fi snapshots use the selected Network's public values; polling does not force a new hardware measurement. collectedAt remains the collection-completion timestamp, not a promise that every native field was sampled simultaneously.
