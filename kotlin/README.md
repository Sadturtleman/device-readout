# DeviceReadout for Kotlin

Kotlin runtime and initial Android collectors, not yet a complete Android release. All 46 typed models/entities are generated from the shared schema. Kotlin 2.1.21, coroutines 1.10.2 and Gradle 8.9 are pinned. Bytecode targets Java 8; the common Instant type uses java.time, available directly on the Android API 26 baseline. The Android library uses AGP 8.7.3 and compileSdk 35.

```kotlin
val fast = access.withPollInterval(250.milliseconds)
val ram: RamSnapshot = fast.get(RamEntity)
fast.watch(RamEntity).collect { snapshot -> render(snapshot) }
```

`watch` returns a cold `Flow<S>` of snapshots. Native event waiting is separate from read deadlines. A bounded dedicated executor isolates blocking OS calls; a cancellation-insensitive collector cannot delay the calling coroutine's read timeout. A context owns its worker and subscription resources; configured views share ownership and close together. Native-event input has a 2048-snapshot bound and fails on overload instead of silently dropping samples. Flow consumers retain normal coroutine backpressure.

The runtime provides get/watch, immutable configuration, typed list/current, descriptions, capabilities, UI/permission observer inputs and lifecycle input. Snapshot normalization copies nested collections into unmodifiable values, converts invalid numeric values to null, and preserves exact unsigned byte counts. `serializeSnapshot` encodes 64-bit integers as decimal strings.

```kotlin
val access = AndroidDeviceAccess.create(applicationContext)
val screen = access.observers.target(DisplayEntity, "application-window")
// Call from the application's own window observer.
access.observers.publish(screen, DisplaySnapshot(pixelSize = Size(width, height)))
access.observers.current(DisplayEntity, screen)
access.observers.sensorActivity(isActive)

access.observers.onPermissionRequest { request ->
    applicationPermissionCoordinator.request(request.entity)
    // The app's permission observer separately publishes the resulting status.
}
access.observers.permission(DisplayEntity, PermissionStatus.Granted)
```

Permission coordination has no read deadline and must dispatch UI work using the application's dispatcher. `get`/`watch` never launch a prompt. Lifecycle inactivity releases sensor subscriptions; resumed collection starts a new session. Late values from an old session are ignored. Sensor `get` waits for a new value, with the ordinary read deadline also applying while inactive.

Permission checks and pending requests inherit an observed entity-kind status when the target has no explicit status. A target observation, including null, overrides that kind status. Publishing a kind status does not complete a pending request for a target that has its own override.

Use `access.observers.failure(entity, DeviceReadoutException(...))` to report an observer failure. A target affects that target; an entity kind affects its whole collection. Permission status is separate: `observers.permission` records status, while `failure` gates collection. For example, publish `PermissionStatus.Denied` and a `PermissionDenied` failure when an app-owned permission observer reports revocation. No SDK prompt or UI lookup is involved.

Failures end affected active streams, interrupt observed first-state waits, and invalidate cached snapshots. Native polling watches receive the failure without waiting for the next poll. Native get/list/current/describe results are discarded if a matching failure occurred during the call, even if the app already cleared it. Recovery uses `failure(entity, null)` and fresh input; state published while failed becomes readable after clearing. Clearing alone does not restore an old snapshot or restart a failed stream. Removed handles remain removed. Native subscription release stays on the collection worker.

Twenty Android state entities currently have native collectors: DeviceInfo, Os, Runtime, Cpu, CpuCore, Ram, AndroidBuild, AndroidIdentity, HardwareSerial, TelephonyIdentity, Power, Battery, Locale, TimeZone, NetworkPath, NetworkPerformance, NetworkInterface, StorageVolume, WifiConnection and CellularSubscription. Power uses broadcasts and API 29+ thermal callbacks; battery uses the OS aggregate target with native events plus polling for current/energy fields. Regional collection preserves app/system language separation and standard identifiers; timezone watches include native events and polling for transitions without complete event coverage. Collection never changes locale/timezone defaults.

Native state callbacks enqueue deferred reads through `DeviceCollector.observeReads`. The runtime executes each read and normalization on its collection worker with the configured timeout, just as it does for get/polling. Network callbacks capture their supplied network/capability/link state, so later OS queries cannot replace a disconnect event with stale connected data. Power, battery, regional and interface notifications request a fresh read instead. Each notification produces a snapshot; equal values are retained. Sensor samples continue to carry their native values through the existing sample path. The public watch result remains `Flow<S>`.

The host app must declare ACCESS_NETWORK_STATE for network path/performance and network-specific DNS/routes; native interface enumeration also requires INTERNET. The library manifest does not add these permissions automatically. Missing required permission produces PermissionDenied, and the SDK starts no permission UI or outbound probe. A declared INTERNET permission here enables Android's native interface enumeration; it does not cause an Internet request. NetworkInterface current selects the interface named by the app's default Android Network, and old discovered handles are tombstoned on removal or OS index replacement.

Seventeen sensor kinds have native adapters: Accelerometer, LinearAcceleration, Gravity, Gyroscope, Magnetometer, RelativeOrientation, AbsoluteOrientation, Illuminance, Pressure, AmbientTemperature, RelativeHumidity, ProximityNear, ProximityDistance, HingeAngle, StepCountSinceBoot, StepDetected and SignificantMotion. Discovery returns typed targets, including multiple absolute-orientation sensors; `describe` is separate from new-sample `get`/`watch`. Hinge values/range/resolution use radians; API 26–29 has no standard hinge sensor mapping. Native callbacks use dedicated HandlerThreads, except the public one-shot trigger API can initially invoke a minimal scalar-copy/post callback on Android's context Looper. Trigger validation/rearming stays off that Looper. App-fed inactivity releases subscriptions, and resuming starts a new collection session. Unknown/invalid state values become null. Malformed event occurrences fail with ReadFailed instead of emitting false/null. Dynamic sensor removal handling exists but still needs hardware verification.

Step counter/detector collection requires the host's ACTIVITY_RECOGNITION permission on API 29+; list/describe do not request it. The SDK never prompts. StepCountSinceBoot preserves the native counter and does not promise background counting after inactivity releases the sensor. StepDetected/SignificantMotion watch waits for actual events without an idle timeout; get waits for the next event with the read timeout. Equal true occurrences are retained. SignificantMotion rearms the native one-shot registration after each occurrence and stops rearming after cancellation. RelativeAltitude/HumanPresence remain explicitly unavailable in the standard Android adapter; pressure/off-body state is not substituted.

CPU core discovery separates present/online processors and process availability; current() is null. Storage current() selects the private app-data volume. Shared storage views are separate targets and may share a backing disk. Native statvfs capacities, read-only status, volume metadata and supported allocation availability are read on the worker. SDK collection creates no directories, allocates no disk space and starts no storage UI. Storage watches combine native removal broadcasts and capacity polling. See the CPU/storage verification report for virtual hotplug evidence and remaining identity-generation limits.

Wi-Fi uses `access.list(WifiConnectionEntity)` and `access.current(WifiConnectionEntity)` for typed connection handles. Native permission/redaction policy controls SSID/BSSID visibility, and negotiated security is available only from API 31. Cellular uses `access.cellularSubscriptions.list()/current()`; its RAT is the selected subscription's current data technology. Metadata discovery requires phone-state access or platform privileges. Both watches combine native callbacks and polling, without opening permission UI or changing network settings.

HardwareSerial reads `Build.getSerial()`; TelephonyIdentity uses `access.telephonyIdentities.list()` for logical modem slots, independently of active SIM subscriptions. The list is ordered by logical slot index; current() is null. Android controls access, including restrictions beyond READ_PHONE_STATE. A readable identifier field survives another field's failure; a wholly denied read is PermissionDenied. Native UNKNOWN/null stays null, with no fallback identifier. Serial watches poll, and API 30+ telephony watches add multi-SIM configuration notifications. Removed targets do not rebind after observed removal, including removal during a read. Physical modem transitions and privileged/owner/carrier/role cases remain unverified.

Fields unavailable from those collectors remain null. Kernel memory is not labeled physical RAM, supported ABI order is not used as the running process architecture, and Android ID is not a universal permanent device identifier. JVM heap headroom is not substituted for ProcessMemory's allocation capacity. Physical sensor/CPU/storage/wireless behavior and the full API/device matrix remain unverified.

Twenty JVM contract tests pass, including observer failures, cache invalidation, worker cleanup and native in-flight result invalidation. Earlier basic API 26/28/36 emulator instrumentation and extended API 26/36 checks cover battery/power events, actual sensor units, quaternion transformation direction and real Activity background/resume supplied through the app's observer. Regional reads and global-default isolation also pass. Network checks include native interface creation/removal/replacement using a local test-only TUN. API 36 additionally verifies thermal events and native timezone changes. The JVM suite includes subscription cleanup under queue pressure and event-triggered read deadlines. Emulator results are x86_64 virtual-device evidence, not proof of physical hardware coverage or the full Android matrix; see the verification reports for which changes were instrumented.

Run `tools/test-kotlin.ps1` from the repository root, or run the included Gradle wrapper with `-p kotlin :core:test`. The PowerShell helper keeps Gradle caches under `.tools`. The wrapper verifies the official Gradle distribution checksum.

Use `tools/build-android.ps1 -SdkRoot <installed-sdk>` for JVM tests, AAR/APK assembly and Android lint. The test target defaults to SDK 35; `-TestTargetSdk 26` checks legacy consumer policy separately from the device's OS version. Applications consuming the library retain their own target SDK. `tools/test-android-device.ps1` installs only on an explicitly named `DeviceReadout_` AVD after checking its identity. Test failure is checked from the instrumentation result, since adb's exit code alone does not report assertion failures. Android test preferences and signing material stay in the project's ignored `.tools` directory.

The build helper also runs thirteen Robolectric Android service contract tests; `-UnitOnly` runs just that suite during adapter development. Its framework artifact cache, resolver lock and temporary directory are scoped to `.tools`, including a shorter temporary path for Windows. Production AAR dependencies do not include Robolectric. Controlled sensor/telephony services replace Android OS behavior only; tests call the public SDK. These fixtures do not replace physical hardware verification.

`-Mode sensorAvailability` compares the new native sensor inventories with SDK capabilities/discovery. `-Mode hingeContracts` requires a project AVD created using `start-android-emulator.ps1 -HingeFixture -ApiLevel 36 ...`; it exercises native 90°→180° events and restores the original angle. A separate native observer first establishes that the Goldfish fixture reached 90°, because its first activation can replay a sentinel or previous angle. Invalid input mapping is tested separately. See `../docs/verification/2026-11-11-sensors.md` for exact evidence and limitations.

The device helper accepts `-Mode all`, `batteryEvents`, `sensorUnits`, `orientationFrame`, `sensorLifecycle`, `regionalContracts`, `timeZoneEvents` (API 30+) and `localeEvents` (API 33+). Fixture mutations affect only the named project AVD or test APK; battery/thermal/timezone settings are restored. Reports are `.tools/DeviceReadout_API<level>-<mode>-results.txt`. See `../docs/verification/2026-11-11.md` for the current evidence.

Network modes are `networkContracts`, `networkEvents` and `interfaceHotplug`. The TUN fixture exists only in the instrumentation APK, accepts only that APK's traffic, has no remote endpoint/default route, and restores its temporary app-op authorization. Network event fixtures restore Wi-Fi/mobile-data settings. See `../docs/verification/2026-11-11-network.md` for results and fixture limits.

CPU/storage modes are `cpuContracts`, `storageContracts` and `storageHotplug`. The last mode requires a name-verified project AVD with no existing removable disks. It creates/formats only the new loop-backed virtual disk, exercises unmount/remount, and disables the virtual disk in cleanup. See `../docs/verification/2026-11-11-cpu-storage.md`.

Wireless modes are `wifiContracts`, `wifiAuthorized`, `wifiEvents`, `cellularContracts`, `cellularDenied`, `cellularRestricted` and `cellularEvents`. Permission fixtures query actual app permission state, preserve test-APK grants and app-op modes, and restore them afterward. Wi-Fi events restore enabled Wi-Fi; cellular events restore the original home registration state. The API 36 image's console roaming setting did not change Android's roaming value, so that transition fixture remains unverified there. See `../docs/verification/2026-11-11-wireless.md` for results and limitations.

Identity modes are `identityContracts` and `identityDenied`, using the same reversible test-APK permission fixture. They compare native values/errors in memory and report no actual serial, IMEI or MEID. API 26 / target 35 verifies permitted values and denial; API 36 / target 35 verifies stronger restrictions; API 36 / target 26 verifies native legacy null/UNKNOWN behavior and denial. See `../docs/verification/2026-11-11-identities.md`.

`tools/start-android-emulator.ps1 -SdkRoot <installed-sdk> -ImageDirectory <x86_64-google-apis-image> -ApiLevel 26 -Port 5582` creates/starts a project-owned headless AVD. It checks both console/adb ports first and accepts an available even console port in 5554–5682. The test helper accepts the matching `-Serial emulator-5582 -AvdName DeviceReadout_API26`. The network checkpoint uses API 36 on port 5586 because another AVD occupied 5584. The dedicated adb server uses port 5047. Stop only the matching project AVD after verification; an adb server may also discover other AVDs, so it is not an ownership boundary.
